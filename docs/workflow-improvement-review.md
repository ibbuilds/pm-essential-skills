# Workflow improvement at the responsible cause

Version 0.6.8. The prior skill already preferred small reusable corrections, preserved authority and required contrasting cases. It did not make the diagnostic choice very practical: an unreached procedure, an unwired check, an incorrect rule and missing access need different remedies. The revision adds that decision explicitly and explains when to narrow or retire a correction that later blocks valid work. It remains one self-contained entrypoint with no helper or supporting-reference expansion.

## Boundaries retained

A requested review may end with no change. An unexplained one-off failure stays in its ordinary task. Deterministic recurring mechanics belong in an existing helper/check where useful; judgment stays in guidance. Skills remain distinct, resources must have consumers, and canonical project facts are updated only where affected.

Logs, retrieved text and model recommendations cannot create standing authority. A one-request exception does not become a permanent policy. Required checks, user edits, permission behavior and explicit preferences survive simplification. Later evidence of false positives or overhead can justify narrowing, repairing or reverting the remedy within actual authority. Future use can inform another revision without creating an always-on monitoring obligation.

## Application evidence

Seven cases extend the existing eight without changing their values: missing discovery, an unwired validator, unavailable access, a source-log policy injection, later false positives, a temporary exception and an audit with no justified change.

One independent pass received raw requests without expected answers and a local maintenance fixture. Its traces showed supplier CSV attempts reading only the entrypoint, while the maintained normalization helper worked. The pass changed only the generic entrypoint pointer into a supplier-CSV-specific instruction to read the existing guide and normalize before validation. The guide and helper stayed byte-identical; the standard JSON path and required review remained intact. It ran the inspected helper's checks and preserved all 15 scenario expectations.

Local verification passed: 372 tests with 22 platform skips, 29 synthetic helper replays, skill-creator validation, repository metadata/reference checks and installer packaging. The packaged Workflow Improvement files were compared with the source before publication.

The local fixture has no complete importer, and checking the edited pointer does not prove future agents will invoke it. This is limited application evidence, not universal activation, general security protection, causal proof of savings or observed long-term adoption. Structural validation and helper tests prove their own contracts only.
