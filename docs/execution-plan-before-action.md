## Contract

Before execution identify the result, path, targets, material risks/dependencies and checks. Tiny exact changes may already be specified and authorized by the user's instruction. A bare goal is not an accepted plan. Read-only preparation remains bounded; it is not implementation or permission for expensive speculative exploration.

Applicable actual user approval, or concrete user steps plus an execution instruction, validates that path. Silence, an announcement, checked box or generated “approved” note does not. Preserve the actual approval reference in current context or existing records. No per-action approvals or mandatory plan file.

Choose ordinary reversible details inside the accepted path. Material changes to outcome, targets, costs, dependencies, risk or authority require validation before affected execution. Unaffected approved work continues. Required checks, stale-evidence invalidation, uncertain-mutation reconciliation and terminal monitoring remain covered.

Task Coordination's small-task wording was reconciled: user-provided steps or accepted plans support direct action, while read-only answers need no implementation plan. Bare Execution Efficiency installation needs no companion. The optional suite renderer points to this procedure before execution; host guidance must point to the actual installed skill.

## Validation limits

Structural tests cannot prove model obedience. Behavioral cases distinguish bare goals from validated steps, silence from consent, actual approval from unrelated notes, routine details from scope expansion, and preparation reads from implementation. Discovery and installed bytes require separate evidence. No measured token saving or universal runtime enforcement is claimed.

An independent eight-case application pass used only the candidate and its conditional reference, with intended answers withheld. It kept bare-goal work in bounded read-only preparation; accepted an exact text replacement as user-provided validated steps; continued an existing approved plan without reapproval; stopped a new paid service pending concrete validation while preserving independent approved work; rejected silence and a generated approval note; answered a simple definition directly; and retained pending CI monitoring. The wait response omitted the host's required periodic status notices, so the entrypoint now explicitly preserves those. The per-action step check was clarified as silent to avoid repetitive narration. These are bounded behavioral checks, not a native activation-rate study.

A separate fresh executor used normal installed skill descriptions and the real global working agreement. Its user request named no skill and supplied a registration-reliability goal without an approved plan. It actually read installed Execution Efficiency and Backend Engineering, proposed bounded inspection followed by a concrete plan for validation, and withheld implementation/external email effects. The new global instruction pointer was observed loaded in the authoring chat as well. This supports the observed selection path, not universal future model obedience.
