## Decision: preserve the current PM behavior

The current owners already handle outcome completion, dependency and capacity
changes, scoped retrieval, governing versions, duplicate evidence, blocked access,
context continuity and proportional workflow improvement. Three source-aware
diagnostic cases passed: capacity bottlenecks despite aggregate spare hours,
historical accepted decisions versus newer drafts/copied evidence, and research
themes without double-counting participants. These were diagnostic walkthroughs,
not blinded model comparisons or measured savings. Negative contrasts avoided
new worksheets, repeated searches or research rituals on adequate simple inputs.

Capacity arithmetic, query planning and theme-coding recipes can add teaching
depth, but no observed failure warranted another mandatory procedure. No new
runtime rules or settings are introduced in this pass. Software product discovery,
strategy and release execution remain SWE responsibilities; PM coordinates work
without replacing them.

## Adaptation boundaries

Do not import all-connected-source fanout, invented relevance weights, fixed
utilization buffers, a mandatory TASKS.md/dashboard/memory directory, automatic
calendar access, recurring reviews, or external contact from source examples.
Retain identity, provenance, authority, actual capacity and outcome checks.

The broader SWE pass adds partial-spec reconciliation and documentation release
timing, consolidates PR/CI convergence, and makes existing calibrated variant
search local to standalone security. PM must carry those actual remaining
obligations through coordination rather than declare success from task checkmarks.

See [validation](broad-validation-2026-10-26.md) for executed checks and limitations.
The [earlier source map](workflow-coverage.md) remains valid within its stated scope.
