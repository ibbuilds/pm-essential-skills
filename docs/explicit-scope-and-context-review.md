# Explicit scope and evidence-based context intervention

Version 0.6.13 addresses two concrete user-reported failures. First, agents infer
extra changes or compensate for incidental effects instead of doing the requested
delta. Second, the unknown-context fallback forced a handoff after three large
outputs even when no evidence established saturation or continuity failure.

## Scope fidelity

Task Coordination now distinguishes implementation mechanics from an additional
outcome. Execution Efficiency and its conditional examples require the explicit
target/delta, prohibit adjacent fixes and compensating changes without instruction,
and use a focused interpretation question only when ambiguity changes the result.
Clear instructions or an accepted clarification need no ritual reconfirmation.
Natural reflow is not permission to redesign another element. A real conflict
with the requested result or a binding obligation is surfaced to its owner.
Existing authorization, verification and unrelated-work protection remain.

Companion SWE Construction and Client Engineering carry the software-specific
boundary independently; no new skill or installation dependency is introduced.
The user is the authority for this requested instruction change; these are not
claims derived from an external benchmark.

## Context intervention

The prior helper returned rollover/domain-work-forbidden for three large outputs,
many turns or a bare critical-history flag without supporting facts. New tests
reproduced those three failures before the change and pass afterward. Counts
now trigger nonblocking reassessment, with no invented percentage or mandatory
warning from count alone. Supported noncritical history can warn/prepare while
work continues. The fresh 40% warning and 60% ceiling remain. A precautionary
pause without telemetry needs declared critical history with distinct concrete
continuity problems. User choices, unsafe-operation stabilization and destination
readiness retain their own rules.

The main entrypoint and policy reference no longer tell agents to pause merely
because three outputs were large. Existing required-policy and continuity tests
were updated to the revised requirement. Three replay fixtures formerly treated
substantial-history alone as a required gate; they now supply an explicit fresh
65% observation to preserve their intended tests of current/stale location choices
and unknown membership at a real gate. Their expected transfer checks remain.
The 29 replay cases are therefore a revised fixture set, not an unchanged baseline
comparison. New proxy tests separately ensure volume alone stays nonblocking.
The bare-package smoke check likewise supplies a fresh ceiling observation to
exercise rollover, rather than assuming a phase/history label establishes it.

expected answers or this review. It moved only Export to the right action group,
preserving Import, Help, labels and all CSS. For a separate file with two Settings
buttons and an ambiguous “move up” request, it asked which target/destination and

forced warning or transfer. The parent inspected the resulting files.

These are synthetic application and code-policy observations, not native host
invocation rates, real token measurements or proof of universal adherence.
Existing hook configuration is unchanged; its native trust step remains distinct
from installing skill updates. No global rule, model, permission, trust store,
telemetry collection or unrelated task changes in this revision.
