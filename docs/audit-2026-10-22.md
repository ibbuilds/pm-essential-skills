# Critical audit: 2026-10-22

Scope: all seven skills, conditional references, deterministic helpers, installer,
recovery, Windows launch paths, packaging, tests, and the claims made about them.
This is a defect-led audit, not a certification of perfection or measured savings.

## Findings and repairs

| Finding | Consequence | Repair / regression evidence |
| --- | --- | --- |
| Interrupted upgrade discarded retired-file originals from the new receipt before restoration | Original user bytes could be lost; ordinary status could miss it | Before/after transaction journal, explicit resumable rollback, fault injection at write checkpoints for install/upgrade/uninstall |
| Atomic replacement and uninstall discarded POSIX mode bits | Restored executable files could stop working | Preserve modes, retain original modes in receipts, refuse recovery over later edits or chmod; legacy receipts do not invent missing originals |
| Windows hook command used argv quoting in a shell command | Quoted executable paths and shell punctuation could prevent the reminder from running | Encoded PowerShell wrapper with literal path arguments; Windows-only actual shell regression, not just string matching |
| Pending location choice depended on current context pressure | Compaction could allow work/transfer before the unanswered choice was resolved | Pending-question check independent of pressure; explicit answers and critical-policy precedence retained |
| Adapter/index described an in-flight transfer as prepared | Notes-only recovery could incorrectly make the source an active writer | Explicit requesting/uncertain states and paused source ownership |
| Forced reread reused old coverage when accepting a cursor | Zero newly emitted content could count as a completed reread | Independent current-pass `reread_spans`; reject skipped prefixes, preserve restart and identity/revision checks |
| Unicode `splitlines()` disagreed with native source line numbers | A requested line could return a different code fragment | LF physical lines, preserving CRLF and embedded Unicode separators; line/offset regressions |
| Archive output could be a packaged source or alias | Building could destroy the manifest/launcher before verification failed | Reject source collisions and unsafe entries; verify a temporary archive before replacing the output; preserve prior outputs on failure |
| Hook input cap silently discarded valid pasted requests above 64 KiB | Optional per-prompt guidance disappeared for ordinary large inputs | Bounded 16 MiB envelope support, neutral handling of malformed/deep input; prompt text is not reflected |
| Stale research row said every decline suppressed future prompts | Maintainers could accidentally undo the authored one-request stay policy | Distinguish persistent opt-outs and setup dismissal from one-request stays |
| Selection boundaries appeared late in several descriptions | Shortened catalogs could lose the useful scope qualifier | Front-load conditional scope; no fixed host truncation cutoff or measured selection gain claimed |

The changes are narrow repairs, not additional mandatory workflow steps. Normal
requests still create no tracker, journal, telemetry, or benchmark. The installer
transaction journal exists only during an installation/removal/recovery operation.

## Current-source review

All references below were checked on October 22, 2026; moving documentation may
change later. Community reports are failure leads, not causal proof or savings data.

- [Codex skill loading and metadata](https://learn.chatgpt.com/docs/build-skills):
  native paths, distinct same-name copies, progressive selection, and shortened
  descriptions. Do not silently migrate users or add duplicate installs.
- [Codex global/project instructions](https://learn.chatgpt.com/docs/agent-configuration/agents-md):
  override precedence and instruction budgets. The exact effective budget for a
  particular host/profile was not established by this audit.
- [Codex hook lifecycle](https://learn.chatgpt.com/docs/hooks): full prompt in the
  input envelope, event-specific additional context, and required trust.
- [Codex shell selection](https://github.com/openai/codex/blob/main/codex-rs/shell-command/src/shell_detect.rs):
  Windows defaults to PowerShell. CreateProcess-style argv quoting is not a
  substitute for a valid shell command.
- [Plugin distribution restrictions](https://developers.openai.com/plugins/build/plugins):
  manual desktop plugin hooks and public-directory eligibility differ.
- [App-server lifecycle](https://learn.chatgpt.com/docs/app-server): archive
  descendants and history-copying forks require care; a fork is not automatically
  a context-reduction strategy.
- [Systematic skill evaluation](https://developers.openai.com/blog/eval-skills):
  actual traces/artifacts matter. A written expected response is not an observed result.
- [Claude skill behavior](https://code.claude.com/docs/en/skills) and
  [instruction loading](https://code.claude.com/docs/en/memory): host-specific
  discovery and invocation controls differ; the Codex installer is not portable.
- [Prompt-cache tradeoffs](https://developers.openai.com/cookbook/examples/prompt_caching_201)
  and [context engineering](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents):
  aggressive context changes can lose useful detail or cached work.
- [Windows hook lifecycle report](https://github.com/openai/codex/issues/40360),
  [handler versus host-dispatch report](https://github.com/openai/codex/issues/21639),
  and [additional-context rendering report](https://github.com/openai/codex/issues/16933):
  concrete reasons to keep host invocation and visible-noise checks separate from
  helper self-tests. These reports do not prove this installation is affected.

## Deliberate limits and residual risks

- The 75/85 pressure policy and repeated long-chat questions remain authored
  policy, not a demonstrated efficiency optimum. A short remaining task or cached
  investigation may be cheaper to continue; compliance and net benefit differ.
- Optional reminders add model-input context and may be visible. They remain
  opt-in, require trust, and fail open for malformed or over-16-MiB envelopes.
- Recovery protects against interrupted processes. It is not a power-loss-safe
  transactional filesystem. Do not edit managed targets during installation or
  recovery; preserve journals when conflicts require manual reconciliation.
- POSIX modes are preserved where supported. Windows ACLs, ownership, and extended
  attributes are not backed up. Older receipts cannot recover modes they never stored.
- Current instructions can be improved and mechanically checked without paid
  evaluations. Live adherence and net savings remain unknown until separately
  authorized execution provides evidence. Do not fill that gap with percentages,
  more prose, or an unconditional “flawless” claim.
