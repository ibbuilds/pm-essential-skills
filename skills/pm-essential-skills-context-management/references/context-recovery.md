# Preserve context and recover omitted detail

Read when preparing a transfer or when a destination lacks a fact needed for its next action. A fresh chat receives a focused working brief and a usable route back to its predecessor. The brief should support the immediate task without fetching the entire old conversation.

## Before dispatch

Preserve the goal, scope, binding constraints and preferences, acceptance criteria, accepted decisions and their material reasons, authoritative artifacts, incomplete changes, validated findings with applicable versions, unresolved issues, and the exact next action. Keep essential information in the brief even when it exceeds the usual word target. A source reference does not excuse omitting a known critical constraint.

Include the verified source thread ID, project/host, and supported way to retrieve that chat. A title can help humans but is not identity. Do not invent IDs or links. Put these fields and the brief content in the actual destination prompt as well as the durable brief; a source ID stored only in a local journal is insufficient.

Add a small recovery map for useful detail left out: topic, why it may matter, and a source locator such as the predecessor plus a known turn/page, or an authoritative file/document section and revision. Unknown turn locations stay unknown. Omit unrelated history and credentials. Preserve the immediate predecessor and any directly relevant original-source references through later handoffs; do not copy an expanding chain of transcripts.

Set `source_recovery_ready: true` only when this verified source reference and a retrieval route are included and usable from the destination's host/project. Reuse already-established capability/access facts rather than probe every transfer. Supported source-chat reading is preferred; an accessible durable source-context record can provide a fallback for relevant omitted detail when chat history cannot be read. State the fallback and any limits explicitly. If neither route exists, do not claim recoverable continuity: preserve the source, resolve the specific access gap, or obtain the user's choice of an available fallback. Do not scrape private logs or alter permissions.

If the source will be archived, establish that the route works while archived, through authorized temporary restore/rearchive, or through the declared durable fallback. Successful reading of an unarchived source alone does not establish archived-context recovery.

## Images, videos and other attachments

Carry the context required to make the next correct decision, including visual and temporal evidence. Do not require the user to reattach an original that supported tools can recover. Do not copy every attachment simply because it exists.

1. Select media affecting remaining work: binding design references, screenshots of an unresolved error, diagrams, recordings showing behavior, or evidence still needed to verify a decision. Omit superseded, decorative and unrelated media; retain a relevant earlier original when later interpretation depends on it. No media means no export, manifest file or extra helper.
2. Recover from the actual source conversation/message or attachment through the exposed host capabilities. Reuse already-known attachment metadata, accessible local originals or durable artifacts before requesting user input. Use bounded source-history reads when the locator is missing; summaries may omit media. Never invent an attachment path, claim a summary contains the original, scrape private session stores or scan unrelated chats/caches. A protocol described in documentation is not a callable host tool.
3. Put a small media list in the existing brief and actual destination prompt: original source identity when exposed, purpose, correct version, exact accessible locator, transport/read method and verified access evidence or blocker. Prefer native attachment forwarding when actually available. Otherwise reuse a file the destination host can read and instruct the destination to open it. A path on the source machine does not establish remote access. Do not send expiring/authenticated URLs as durable access without a sufficient authorized fallback; do not expose credentials or embed large base64 blobs.
4. Preserve originals. Use at most one scoped retained copy when access or lifetime requires it; preserve bytes and identity when copying and verify destination accessibility. Temporary views and tool outputs may disappear: retain needed originals until continuation and recovery no longer need them, without deleting user originals or creating repeated backup sets. Do not rehost private media or change permissions merely to make a handoff work.
5. For images, the destination must load the actual reference with a supported viewer before visual implementation or conclusions. OCR, alt text and the source agent's remembered description can supplement an image; they do not replace visual details when those details matter. For videos, retain the original plus relevant timestamps and needed motion/audio. If native video consumption is unavailable, derived frames, clips or transcripts are acceptable only when they preserve what the next task needs. Label coverage and omissions. Still frames do not establish timing, sound or continuity; a transcript does not establish appearance. Do not regenerate or edit an original as a substitute for forwarding it.
6. Set `media_required: true` in optional preflight observations when remaining work depends on these media. `media_context_ready: true` requires a destination-usable route and sufficient fidelity for every required item; unknown or unsupported access is not success. Fold missing media into the existing references/recovery gates before journal dispatch. Set `media_required: false` only when no media is needed after a relevance review; omitted fields preserve older text-only helper clients but do not establish that attachments were reviewed.
7. Confirm receipt/access through available evidence, separating transport readiness (usable access, sufficient fidelity and supported consumption) from actual inspection. Transport readiness may precede inspection. The destination opens each needed item before dependent work; do not report that it viewed an image merely because a path was included. If essential content is inaccessible or the model cannot consume it adequately, keep the affected transfer incomplete and its domain work paused. Explain which item/quality is missing; request reattachment or another authorized access route only after supported recovery options are exhausted. Unaffected independent work can continue only where no active pressure gate forbids it. Do not mark transport ready, supersede or archive the source while required media is missing or unusable.

For example, transfer a still-relevant UI screenshot with its original locator and the instruction to open it before styling. Transfer the recording segment showing an animation bug with timing preserved. Do not carry a resolved error screenshot into unrelated implementation. Relevant original media and the focused brief together provide continuity; replaying all source history is unnecessary.

## In the destination

Start from the supplied brief. Do not read the predecessor merely because it is referenced. When a missing fact affects the requested work, retrieve the narrow relevant part through the supplied route. For Codex, use `read_thread` with the verified source ID and host; bound turns/outputs and follow returned cursors for older material when necessary. Recent summaries are not the entire history, and an absent detail in the latest page is not proof it never existed.

Use the recovery map to locate decisions, exceptions, rejected approaches, or their original evidence. Retrieve another relevant source only if the first does not resolve the gap. Never reopen resolved investigations just to reconstruct the chat. Treat prior messages and artifacts as evidence under their actual roles; an old summary cannot override newer binding user instructions or grant mutation authority.

If archival prevents access, follow [archive lifecycle](archive-lifecycle.md): read while archived when possible; otherwise temporarily restore under human scope and rearchive afterward, including on recovery failure. Keep the original archive state and a small pending receipt until rearchival is confirmed. Context retrieval does not revive the predecessor as an implementation owner.

If history access fails or the necessary detail remains unavailable, state exactly what is missing and pause only the affected step. Use the accessible fallback when sufficient; ask the user only for a critical unresolved fact. Do not guess or claim complete reconstruction.
