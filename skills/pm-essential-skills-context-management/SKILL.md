# PM Essential Skills / Context Management

Keep usable context and preserve decisions needed to finish. Apply during work without user reminders. Loading this file once does not complete the recurring check.

## Check early, using real evidence

Before substantive work each user turn, after large output and before consequential action, apply this check, including in skill-created continuations. Use fresh **current-context tokens / effective context-window tokens** when exposed, including instructions, tools and conversation. Account allowances, lifetime usage and chat age are not occupancy. Never invent percentages or inspect private session storage to obtain them.

| Current evidence | Required behavior |
| --- | --- |
| Fresh occupancy below 40% | Continue related work; reuse decisions and evidence. |
| Fresh occupancy 40% to <60% | Warn and prepare a fresh-chat continuation. Current work may continue; do not treat this warning alone as a stop. |
| Fresh occupancy >=60% | Ceiling reached. Only stabilize an already-running unsafe operation, preserve state and complete the handoff. Never finish another feature here first. |
| No fresh telemetry | Label occupancy unknown. Message/output counts invite reassessment, never establish saturation or require a handoff alone. Use concrete continuity evidence; repeated lost constraints or reconstruction that drops active obligations can justify a safe continuation. |

Assess long chats from relevant visible evidence. Superseded history can justify warning/preparation; a forced pause without telemetry needs supported continuity failure. A small answer needs no helper, scan or state file.

## Keep the change pending until resolved

At 40%, state the observation and prepare continuation. At 60%, announce the pause. With unknown occupancy, name the actual structural evidence.

From 40%, remind once per subsequent user turn while pressure persists, including after “stay here.” At 60% or a supported critical heuristic, pause substantive work. Preserve pending choices; a reminder need not repeat an unanswered location question. Avoid repeated in-turn notices, polling or duplicate destinations. Prior notices, cost and missing tools cannot clear the gate; explain blockers and the fallback.

Separate location choice from notification policy. An ordinary “stay here” covers this logical request and related corrections; never promote it to permanent stay, disabled management or suggest-only. Reassess on the next request. Continuing, completing a task or already warning does not reset pressure. Only an explicit lasting user preference changes future management.

Keep evidence, pending warning/choice and temporary choice scope in current context or existing handoff state. A verified fresh destination or effective compaction retaining essential decisions resets pressure. Fresh occupancy below 60% clears the hard gate; 40% to <60% retains reminders; below 40% clears them. Unknown telemetry alone proves no reset.

## Preserve a useful continuation

Use an existing brief or the [handoff template](assets/handoff-template.md): goal, constraints and accepted decisions, current files/revision and uncommitted changes, active error, exact verification commands/results and limits, pending operations/approvals, next action and relevant enabled skills. Reference durable artifacts instead of copying logs. Redact secrets. Reuse suitable storage; do not produce per-turn logs or backup copies.

Carry necessary media with original provenance, purpose and verified destination access. Recover originals through supported tools; a summary or pathname proves neither delivery nor inspection. The destination opens media before dependent work. Missing essential media keeps transfer incomplete. Read [media recovery](references/context-recovery.md#images-videos-and-other-attachments) when needed; reuse originals.

For actual transfers read [runtime readiness](references/runtime.md), [context recovery](references/context-recovery.md) and the [Codex adapter](references/codex-desktop.md). Create only with explicit human authorization and supported tools; do not fork for a fresh context. Confirm destination readiness before ending source ownership; reconcile ambiguous creation before retrying. Unsupported transfer means a ready-to-copy brief and a paused source. [Archive rules](references/archive-lifecycle.md) apply only when separately authorized.

For measurement, helper fields and optional advisory mode read [policy](references/policy.md). [Request choices](references/existing-chats.md) govern optional below-trigger moves; [project setup](references/project-setup.md) is conditional. [Automatic activation](references/automatic-activation.md) explains host discovery and its limits. A skill defines required behavior; deterministic runtime enforcement requires host support and cannot be promised by Markdown alone.
